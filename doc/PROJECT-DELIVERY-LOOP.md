# 项目交付闭环

> 状态：第二阶段最小闭环的产品与实现基线
> 交付方法：数字孪生（故事驱动）
> 更新日期：2026-07-28

## 对象层级

```text
项目 → 固定六阶段 → 任务组 → 可执行任务 → 交付物及版本
```

- 阶段是项目生命周期对象，不是普通任务。
- 任务组只负责组织任务，状态和进度由子任务汇总。
- 新交付法项目中的任务必须归属阶段和任务组；历史项目不强制迁移。

## 固定六阶段

阶段名称和顺序固定，不允许删除、改名或调整：

1. Discover
2. Scope
3. Go/No-Go
4. Implement
5. Business Case
6. Maintenance

项目创建时由系统确定性创建六阶段和 26 个默认任务组。只有 Discover 初始激活，其他阶段可见但锁定。

## 默认任务组

- Discover：项目范围确定、入场准备。
- Scope：投标文件调研、硬件信息调研、业务调研、模型调研。
- Go/No-Go：需求与设计文档编写及评审、系统建模、原型设计及评审、高保真设计及评审、Go/No-Go决策确认。
- Implement：测试策划与文档、开发需求传递、功能开发、部署实施、迭代评审与优化、系统测试、数据对接与生产验证。
- Business Case：系统试运行、用户文档与培训、验收准备与价值呈现、正式验收。
- Maintenance：运维交接、项目归档、项目复盘与经验沉淀、后续需求与N+1展望。

## 项目创建与任务骨架

- 当前交付方法只有“数字孪生（故事驱动）”。
- 项目经理必选且唯一，必须是项目所属公司的有效用户。
- 没有可用 PM Agent 时允许创建，但不能发起自动骨架生成。
- 最终验收负责人、计划开始日期和目标完成日期允许创建时待确认。
- 项目初始状态为“规划中”。
- 系统只创建固定阶段和默认任务组，不虚构项目具体任务。
- PM Agent 根据已提供材料和对话生成覆盖全部默认任务组的任务骨架，缺失事实必须标记“待确认”。
- 每个必选任务在基线确认前必须有且只有一名负责人。
- 交付物任务必须声明交付物、必选性和唯一人类终审人；门禁任务必须指定人类决策人。
- 计划开始日期和目标完成日期补齐后，项目经理一次性确认骨架并建立基线；确认骨架不自动结束 Discover。

## 任务、交付物和评审

- 普通执行任务由负责人完成。
- 交付物任务由负责人提交版本，唯一终审人批准或驳回。
- 门禁任务只能由人类决策人完成。
- 一个任务可包含多个交付物，支持文件、外部链接和文本。
- 每次提交生成不可变版本；获批版本成为正式版本，历史版本保留。
- 评审结果只有“批准”或“驳回”；小问题通过后续任务处理。

## 进度、推进和退回

- 任务组、阶段和项目进度按“已完成必选任务数 / 必选任务总数”自动计算；可选任务不计入。
- 阶段推进必须满足：骨架已确认、必选任务完成、必选交付物获批、没有阻塞高风险。
- Discover 进入 Scope 前必须确认最终验收负责人。
- PM Agent 负责建议，只有项目经理可以确认推进。
- 阶段退回必须记录原因，下游未完成任务转为阻塞。
- Maintenance 完成后，由项目经理确认推进，项目才进入“已完成”。

## 基线后的变更

- 范围内普通任务调整可由阶段负责人处理。
- 阶段、任务组、里程碑、必选交付物、关键依赖或基线变化需要项目经理批准。
- 合同范围外变更进入正式变更控制。

## 本阶段不包含

- 其他交付方法及项目类型自动路由。
- Skill 飞轮和 Nacos 治理。
- 工时或权重进度。
- Agent Work 集成。
- 历史项目强制迁移。
