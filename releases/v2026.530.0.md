# v2026.530.0

> Released: 2026-05-30

## Highlights

- **OpenClaw Gateway v4 support** - The OpenClaw Gateway adapter now negotiates protocol 3..4, keeps protocol 3 compatibility, and works with current v4-only gateways that reject legacy root-level `paperclip` agent params. ([#109](https://github.com/penclipai/paperclip-cn/pull/109), @penclipai)
- **Packaged Windows desktop/runtime path** - The packaged `penclip` CLI and Electron runtime were verified after bundling workspace code, including Windows desktop packaging for Paperclip CN. ([#107](https://github.com/penclipai/paperclip-cn/pull/107), @penclipai)
- **Broader Simplified Chinese UI coverage** - The CN fork closes another round of untranslated UI gaps across issue detail actions, nested settings surfaces, dialogs, sidebars, and runtime messages. ([#107](https://github.com/penclipai/paperclip-cn/pull/107), [#109](https://github.com/penclipai/paperclip-cn/pull/109), @penclipai)

## Improvements

- **Gateway diagnostics** - OpenClaw Gateway failures now give clearer guidance for protocol mismatch, invalid request params, auth/token failures, pairing-required states, and challenge timeouts.
- **Gateway environment testing** - Adapter probes now advertise the supported protocol range and report successful protocol 4 connects, making configuration checks easier to interpret.
- **Release verification budget** - Canary verification has a longer timeout so the full test and build gate can finish instead of being interrupted mid-release. ([#108](https://github.com/penclipai/paperclip-cn/pull/108), @penclipai)
- **Fork maintenance tooling** - The CN fork now includes reproducible i18n key audit tooling and updated fork-maintenance guidance for upstream sync, localization, Windows, Electron, adapter, and rebrand checks.

## Fixes

- Fixed v4 OpenClaw Gateway runs failing with `unexpected property 'paperclip'` during the `agent` request.
- Fixed remaining untranslated IssueDetail pause/resume/sub-issue controls observed during zh-CN audit.
- Fixed packaged `penclip` CLI resolution after desktop/runtime bundling.
- Preserved CN fork boundaries while absorbing the upstream skills catalog and related upstream structure.

## Upgrade Guide

- No database migration or manual config migration is required.
- Existing protocol 3 OpenClaw gateways remain supported.
- For protocol 4 OpenClaw gateways, keep the existing gateway URL/token/device-key config; the adapter will negotiate protocol 4 automatically.
- If an OpenClaw agent reports a missing `paperclip-claimed-api-key.json`, rerun or complete the agent API-key claim/bootstrap flow; that is separate from Gateway protocol negotiation.
