# Paperclip v2026.703.0

> Released: 2026-07-03

This is the next `latest` release after `2026.608.0`, so it folds in the user-facing work from the 2026.609, 2026.618, and 2026.626 stable notes plus the follow-up fixes validated on the 2026.703 canary line.

## Highlights

- **Artifacts and workspace outputs are first-class** - Company Artifacts, richer issue attachments, video previews, workspace file viewing, workspace downloads, and external object references make agent output easier to inspect without digging through raw run logs. ([#7621](https://github.com/paperclipai/paperclip/pull/7621), [#7681](https://github.com/paperclipai/paperclip/pull/7681), [#8512](https://github.com/paperclipai/paperclip/pull/8512))
- **Skills Store and installable capabilities** - Skills are now managed through an in-app store with install counts, category editing, and a dedicated `skills:create` permission, giving operators a cleaner way to extend agent capability while keeping mutation rights scoped. ([#7990](https://github.com/paperclipai/paperclip/pull/7990), [#8615](https://github.com/paperclipai/paperclip/pull/8615), [#8616](https://github.com/paperclipai/paperclip/pull/8616))
- **Task watchdogs, ask mode, and richer interactions** - Task watchdogs can monitor issue subtrees, ask-mode issues support answer-only work, checkbox confirmations can carry structured selections into continuations, and superseded questions expire when newer comments take over. ([#8339](https://github.com/paperclipai/paperclip/pull/8339), [#8334](https://github.com/paperclipai/paperclip/pull/8334), [#7649](https://github.com/paperclipai/paperclip/pull/7649), [#8893](https://github.com/paperclipai/paperclip/pull/8893))
- **Sandboxed execution is more visible and reusable** - Self-hostable Kubernetes sandboxes, Novita support, reusable Daytona leases, reusable custom images, live sandbox runtime status, sync-progress reporting, and live agent feedback during sandboxed runs make remote execution less opaque. ([#5790](https://github.com/paperclipai/paperclip/pull/5790), [#7938](https://github.com/paperclipai/paperclip/pull/7938), [#8513](https://github.com/paperclipai/paperclip/pull/8513), [#8794](https://github.com/paperclipai/paperclip/pull/8794), [#8915](https://github.com/paperclipai/paperclip/pull/8915))
- **Security and tenant isolation foundations** - Per-company JWT signing keys, company-scoped cloud tenants, plugin table tenant keys, stricter issue read checks, CEO same-company hardening, token/password log redaction, and hardened Work Timeline filters reduce cross-company and credential exposure risk. ([#5864](https://github.com/paperclipai/paperclip/pull/5864), [#7525](https://github.com/paperclipai/paperclip/pull/7525), [#5865](https://github.com/paperclipai/paperclip/pull/5865), [#8346](https://github.com/paperclipai/paperclip/pull/8346), [#8276](https://github.com/paperclipai/paperclip/pull/8276), [#8923](https://github.com/paperclipai/paperclip/pull/8923))
- **Paperclip CN release path is healthy again** - The CN fork keeps zh-CN defaults, Windows compatibility, Electron packaging, rebrand boundaries, and adapter-package boundaries intact while the Docker image, canary publish, release smoke, and onboarding smoke gates have been repaired for this promotion.

## Improvements

- **Agent run reliability** - Execution locks, checkout run IDs, reassignment, startup reaping, active-run cleanup, process-loss retry expectations, and workspace branch coherence all received hardening so agents recover from interrupted work with fewer manual repairs.
- **Local adapters and model routing** - `codex_local`, `claude_local`, `gemini_local`, `opencode_local`, and `pi_local` gained gateway routing, session recovery, safer auth handling, clearer refusal/error signals, model-list updates, and Gemini 3.1 Pro support. ([#7919](https://github.com/paperclipai/paperclip/pull/7919), [#7837](https://github.com/paperclipai/paperclip/pull/7837), [#8314](https://github.com/paperclipai/paperclip/pull/8314), [#1602](https://github.com/paperclipai/paperclip/pull/1602))
- **Onboarding, navigation, and daily UI polish** - The refreshed onboarding flow, streamlined sidebar default, task status icons and colors, project typeahead in command palette, mobile issue-chat fixes, improved scroll restoration, and accessibility updates make the board easier to scan and operate. ([#8628](https://github.com/paperclipai/paperclip/pull/8628), [#8496](https://github.com/paperclipai/paperclip/pull/8496), [#8580](https://github.com/paperclipai/paperclip/pull/8580), [#8773](https://github.com/paperclipai/paperclip/pull/8773), [#1913](https://github.com/paperclipai/paperclip/pull/1913), [#1939](https://github.com/paperclipai/paperclip/pull/1939))
- **Routines, pipelines, and recurring work** - Routine date variables, sorted workspace routines, routine detail polish, and pipeline workflow primitives add more structure for recurring and multi-stage work. ([#8655](https://github.com/paperclipai/paperclip/pull/8655), [#8666](https://github.com/paperclipai/paperclip/pull/8666), [#7903](https://github.com/paperclipai/paperclip/pull/7903))
- **Environments and workspace controls** - Execution environments are instance-scoped, custom images are scoped to instance environments, workspace overview payloads are bounded, and reusable workspace selector search is sharper. ([#8375](https://github.com/paperclipai/paperclip/pull/8375), [#8850](https://github.com/paperclipai/paperclip/pull/8850), [#8627](https://github.com/paperclipai/paperclip/pull/8627), [#8597](https://github.com/paperclipai/paperclip/pull/8597))
- **Telemetry and live status** - Generated telemetry client types, interaction-resolved events, live descendant status in inbox rows, and clearer run/debug metadata improve observability for both product flows and maintainers. ([#8818](https://github.com/paperclipai/paperclip/pull/8818), [#8824](https://github.com/paperclipai/paperclip/pull/8824), [#8876](https://github.com/paperclipai/paperclip/pull/8876))

## Fixes

- **Issue and comment correctness** - Agent-authored comments no longer render as Board, cancelled child blockers no longer hold parent attention hostage, issue create responses include relation summaries, and issue-thread reads enforce the expected access checks. ([#8833](https://github.com/paperclipai/paperclip/pull/8833), [#7577](https://github.com/paperclipai/paperclip/pull/7577), [#8901](https://github.com/paperclipai/paperclip/pull/8901))
- **Sandbox and workspace edge cases** - Sandbox restore diagnostics, clean-branch drift recovery, sandbox bridge credentials, large uploads, git publishing, transient Codex home sync exclusions, and branch refresh behavior were tightened across local and remote execution. ([#8903](https://github.com/paperclipai/paperclip/pull/8903), [#8914](https://github.com/paperclipai/paperclip/pull/8914), [#8844](https://github.com/paperclipai/paperclip/pull/8844))
- **Secrets and config safety** - Secret reference binding stays in sync across agent lifecycle flows, remote Claude config is isolated from local credentials, and read-only config endpoints no longer require elevated create permissions.
- **Desktop, Docker, and install flow** - Desktop shell scroll/layout regressions were fixed, Docker remains compatible with Railway and the CN fork's adapter packaging boundary, and published CLI/package manifests remain installable through the release flow.
- **Release smoke and CI stability** - Canary publish verification, npm auth, release smoke follow-up jobs, onboarding smoke selectors, GitHub PR checks, Windows Vitest path assumptions, and Docker multi-arch builds were repaired so the stable promotion is backed by the current gates.

## Upgrade Guide

- No manual breaking migration is required. Normal server startup applies the included database migrations.
- Docker users should pull/build the new image rather than carrying forward custom Dockerfile lines that copy stale adapter package paths.
- If you run Paperclip CN with external adapter packages, keep those installed through Adapter Manager or your configured plugin path; the core image no longer relies on stale Hermes package manifest copies.
- If you are upgrading from the current npm `latest` (`2026.608.0`), expect a larger-than-usual migration window because this promotion includes several weeks of canary-validated schema and control-plane changes.
